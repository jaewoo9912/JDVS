# Unit 4 — 메모리와 레지스터

> 핵심 질문: 레지스터·메모리는 왜 나뉘고, 데이터는 어디에 사는가?

## 0. 큰 그림

ALU가 `a+b`를 계산할 때 `a`,`b`는 어디서 오고 결과는 어디로 가나? 컴퓨터엔 데이터를 담는 장소가 여러 종류고, 각각 **속도·크기·비용이 극단적으로 다르다.** 이 "저장 장소의 위계"가 Unit 11~14(캐시·가상메모리)의 씨앗.

## 1. 근본 딜레마 — 빠른 것은 작고, 큰 것은 느리다

```text
        빠름  ◄──────────────►  느림
        작음                    큼
        비쌈                    쌈
```

빠르고 큰 메모리는 미친 듯 비싸고 전력 폭발 → 불가능. 그래서 **빠르고 작은 것**과 **느리고 큰 것**을 둘 다 두고 역할 분담:

```text
레지스터 : 극소수(수십개), 극빠름(1사이클), 코어 안
 (캐시)  : 중간 (Unit 11)
메모리   : 거대(수GB), 느림(수백 사이클), 코어 밖
```

## 2. 레지스터 — CPU의 "손 안의 작업대"

> 레지스터 = CPU 코어 안의, 극소수 초고속 저장 칸.

- **개수 적음** (보통 32개, RISC-V `x0`~`x31`). 명령어에 레지스터 번호를 비트로 박아야 해서(32개=5비트). 많으면 명령어 비대·회로 느려짐.
- **극빠름** — ALU 옆, 1사이클 read/write.
- ALU 입출력은 거의 항상 레지스터. 32개 묶음 = **레지스터 파일**(보통 2 read + 1 write/사이클).
- 비유: 요리사의 **도마 위 공간**. 좁지만 손이 바로 닿음.

## 3. 메모리 — 거대한 창고

> 메모리(DRAM) = 주소로 접근하는 거대하지만 느린 공간.

- **주소로 접근**: 번호 매긴 칸들의 배열. "1000번지 값 줘".
- **거대**(수GB) · **느림**(코어에서 멀고 구조상 수백 사이클).
- 비유: 요리사 뒤의 **대형 창고**. 갔다 오는 데 시간 걸림.
- byte 단위 주소 + word(4/8B) 단위 접근 → endianness 이슈.

## 4. 둘을 잇는 다리 — Load / Store

```text
LOAD  : 메모리 → 레지스터  (창고→도마)
STORE : 레지스터 → 메모리  (도마→창고)

예) LOAD x2←[1000]; LOAD x3←[1004]; ADD x1=x2+x3; STORE [1008]←x1
```

> CPU는 메모리에서 직접 계산 안 함. 레지스터로 가져와(load)→계산→저장(store) = **load-store 아키텍처**(RISC-V·ARM).

## 5. 왜 이 구조인가 — 위계의 시작

- 레지스터 수백만 개? → 명령어 주소 비트 폭발 + 커지면 느려짐(빠름의 이유가 "작아서").
- 메모리만? → 너무 느려 ALU가 굶음.

→ 빠르고 작은 레지스터 + 느리고 큰 메모리 + load/store. 그 격차(1 vs 수백 사이클)가 **캐시(Unit 11)**를 낳음. 저장 위계의 출발점.

## 핵심 정리

- 저장은 빠름↔큼↔쌈 트레이드오프 — 다 가질 수 없다.
- 레지스터(코어 안, ~32개, 1사이클) ↔ 메모리(주소 접근, 거대, 수백 사이클).
- load/store가 다리. CPU는 메모리에서 직접 계산 안 함.
- **Golden rule:** "빠른 건 작고 비싸다" → 레지스터+메모리 분담, 그 격차가 캐시를 낳는다.

## 🔌 검증 관점

- **레지스터 파일 read/write 위험:** 같은 사이클 같은 레지스터 write&read → 새 값? 옛 값?(정책) → 모델이 맞춰야 함. Unit 8 hazard의 씨앗.
- **`x0` 하드와이어:** RISC-V `x0`=항상 0(써도 무시). 모델이 일반 레지스터로 다루면 버그.
- **Endianness:** word 저장 시 바이트 순서(little/big) 다르면 데이터 "맞는데" 뒤집혀 mismatch. RDMA/네트워크는 byte order가 핵심 버그원.
- **Byte enable/부분 쓰기, reset value** 코너.
- **메모리 모델:** 멀티마스터(CPU+DMA)에선 단순 배열 추상이 깨짐 → Unit 13/16, IOMMU/RDMA 직결.

## 📎 부록 — 이 단원에서 나온 질문들

### Q1. DRAM은 시스템 상 물리적으로 어디에 있는거야?

"느리다"는 게 추상적인데, **물리적으로 어디 있는지** 보면 왜 느린지 바로 이해된다.

**위치별 위계 — 가까울수록 빠르다**

저장장치는 CPU 코어로부터의 **물리적 거리** 순으로 배치된다:

```text
┌─ CPU 칩(다이) 안 ──────────────────────┐
│  레지스터    ← 코어 바로 안. 1사이클        │
│  L1/L2 캐시  ← 코어 옆/근처 (Unit 11)      │
│  L3 캐시     ← 칩 안 공유 영역             │
│  [메모리 컨트롤러] ← 요즘은 CPU 다이에 통합! │
└──────────┬──────────────────────────────┘
           │ 메모리 채널 (수 cm의 배선, 메인보드 위)
           ▼
┌─ 메인보드 위, CPU 밖 ────────────────────┐
│  DRAM 모듈 (DIMM) ← 슬롯에 꽂힌 막대기들    │  ← 여기!
└──────────────────────────────────────────┘
           │ (훨씬 멀리)
           ▼
   SSD/HDD (저장장치, 더 느림)
```

**DRAM은 정확히 어디?**

> **DRAM은 CPU 칩 *밖*, 메인보드 위의 "DIMM 슬롯"에 꽂힌 메모리 막대기(모듈)들**이다.

- 데스크탑/서버 열어보면 CPU 쿨러 옆에 길쭉한 막대기 여러 개 꽂혀 있는 것 — 그게 **DIMM(Dual In-line Memory Module)**, 그 위에 DRAM 칩들이 붙어 있다.
- CPU와는 **메모리 채널**이라는 배선(메인보드 위 수 cm)으로 연결된다.
- 즉 레지스터·캐시는 **CPU 칩 안(on-die)**, DRAM은 **칩 밖, 보드 위(on-board)**. 이 물리적 분리가 핵심.

**왜 이 위치가 "느림"을 만드나**

1. **거리:** 전기 신호도 빛 속도 한계가 있어, 칩 안 1mm와 보드 위 수 cm는 왕복 시간 차이가 큼.
2. **칩 경계를 넘음:** CPU 다이 → 패키지 핀 → 보드 배선 → DIMM → 다시 돌아옴. 경계를 넘을 때마다 지연·전력.
3. **DRAM 자체 구조:** 커패시터 기반이라 읽는 데 시간이 걸리고 주기적 refresh 필요 (Unit 14에서 상세).

→ 그래서 레지스터 1사이클 vs DRAM 수백 사이클. **물리적으로 멀고 칩 밖이라** 느린 것.

**메모리 컨트롤러 — 옛날 vs 지금 (중요한 변화)**

DRAM에 접근하려면 "메모리 컨트롤러"가 필요하다. 위치가 바뀌었다:

```text
옛날: CPU ── [노스브리지 칩(별도)] ── DRAM    (컨트롤러가 칩 밖 → 더 느림)
지금: [CPU 다이 안에 메모리 컨트롤러] ── DRAM   (통합 → 거리 단축, 빨라짐)
```

요즘 CPU는 메모리 컨트롤러를 **다이 안에 넣어서**(integrated memory controller) DRAM까지의 경로를 줄였다. 이게 von Neumann 병목(Unit 1)과 싸우는 한 방법.

**변종 — 가속기의 HBM**

GPU·NPU·고성능 가속기는 DRAM이 너무 멀어서, **HBM(High Bandwidth Memory)**을 쓴다:

```text
[GPU/가속기 다이] ─ (아주 짧은 인터포저) ─ [HBM 스택]
   → 같은 패키지 안(on-package)에 메모리를 쌓아 올려 거리를 극단적으로 줄임
```

- DRAM을 **수직으로 쌓아(stack)** 칩 바로 옆 같은 패키지에 둠 → 대역폭 폭발, 거리 단축.
- ML 가속기·고성능 NIC이 HBM을 쓰는 이유 = "데이터 공급이 병목(memory bound)"이라서 (Unit 17 예고).

**한 그림 요약**

```text
거리 ──►  멀어질수록 느리고 큼

[코어]레지스터 → L1 → L2 → L3 → │칩경계│ → DRAM(DIMM,보드 위) → SSD
 on-die ─────────────────────────       on-board / 패키지 밖
                                  ↑
                          여기서 속도가 뚝 떨어짐 (병목)
```

**정리**

- **DRAM = CPU 칩 밖, 메인보드의 DIMM 슬롯에 꽂힌 메모리 모듈.** 레지스터·캐시는 칩 안(on-die).
- 칩 밖 + 멀리 + DRAM 구조 → 수백 사이클 지연 (von Neumann 병목의 물리적 실체).
- 메모리 컨트롤러는 요즘 **CPU 다이에 통합**돼 경로 단축.
- 가속기는 **HBM(on-package 적층)**으로 거리를 극단적으로 줄여 대역폭 확보.

### Q2. HBM은 뭐야?

**HBM = High Bandwidth Memory (고대역폭 메모리)**

한마디로: **DRAM을 수직으로 쌓아서, 프로세서 바로 옆 같은 패키지에 붙인 메모리**다. "멀리 있는 DIMM" 문제를 거리·폭 양쪽으로 해결한 것.

**일반 DRAM(DIMM)과 뭐가 다른가**

```text
일반 DRAM (DIMM):
   CPU ──(메모리 채널, 보드 위 수 cm)── [DRAM 칩들이 옆으로 나란히]
        좁은 길(64비트씩) × 몇 채널, 멀리 있음

HBM:
   [프로세서 다이] ─(인터포저, 수 mm)─ [DRAM을 수직으로 쌓은 탑]
        엄청 넓은 길(1024비트+), 바로 옆
```

차이를 만드는 두 가지 핵심:

**① 3D 적층 (수직으로 쌓기)**
일반 DRAM은 칩을 보드에 **옆으로** 깔지만, HBM은 DRAM 다이를 **위로 여러 층 쌓아** 탑을 만든다. 그리고 층들을 **TSV(Through-Silicon Via, 실리콘 관통 전극)**라는 수직 배선으로 관통해 연결한다. → 같은 바닥 면적에 훨씬 많은 메모리.

**② 인터포저 + 초광폭 버스**
프로세서와 HBM 탑을 **인터포저(interposer)**라는 작은 실리콘 받침판 위에 나란히 올려, 아주 짧고 **엄청 넓은 길(1024비트 이상)**로 연결한다. 일반 DRAM이 64비트 길이라면 HBM은 그 16배 넓은 길.

> 비유:
>
> - 일반 DRAM = 창고가 **멀리** 있고, 오가는 길이 **2차선 도로**.
> - HBM = 창고를 **바로 옆에 고층으로** 짓고, 길을 **32차선 고속도로**로 깔음.
>
> → 한 번에 훨씬 많은 데이터가, 훨씬 가까이서 쏟아져 들어옴 = 고대역폭.

**왜 만들었나 — 대역폭(bandwidth)이 목적**

이름 그대로 **"고대역폭"**이 핵심. 여기서 두 용어 구분이 중요:

```text
지연(latency)    = 한 번 갔다 오는 데 걸리는 시간 (왕복 시간)
대역폭(bandwidth) = 단위 시간에 옮길 수 있는 총량 (길의 폭)
```

HBM은 주로 **대역폭**을 극대화한다 — "데이터를 *얼마나 많이* 동시에 퍼올 수 있나". GPU·NPU 같은 가속기는 한 번에 어마어마한 양의 데이터(행렬·텐서)를 먹어치우니, **좁은 길로는 굶어 죽는다(memory bound).** 그래서 초광폭 HBM이 필수.

**Trade-off (왜 모든 데 안 쓰나)**

| | 일반 DRAM (DIMM) | HBM |
|---|---|---|
| 대역폭 | 보통 | **매우 높음** |
| 용량 확장 | 슬롯에 더 꽂으면 됨 (유연) | 패키지에 고정 (확장 어려움) |
| 비용 | 쌈 | **비쌈** (적층·인터포저 공정) |
| 교체/업그레이드 | 가능 | 불가 (칩에 붙박이) |

→ 그래서 **일반 PC/서버는 DIMM**(싸고 용량 유연), **GPU·AI 가속기·고성능 네트워크 칩은 HBM**(대역폭이 생명)으로 갈린다.

**검증 분야와의 연결**

- **AI 가속기(NPU/GPU):** 텐서 연산이 데이터 폭식 → HBM 없으면 연산 유닛이 굶음. 그래서 요즘 AI 칩은 거의 HBM.
- **고성능 NIC/RDMA:** 초고속으로 들어오는 패킷·DMA 데이터를 버퍼링하려면 높은 대역폭 메모리가 유리.
- **검증 관점 예고:** "가속기가 기대만큼 안 빠르다" → compute-bound인지 **memory(=대역폭) bound**인지 판정하는 게 핵심인데(Unit 17), HBM은 바로 그 memory bound를 풀려는 하드웨어적 답.

**정리**

- **HBM = DRAM을 3D로 쌓고(TSV) 인터포저로 프로세서 바로 옆에 초광폭 버스로 연결한 메모리.**
- 목적 = **대역폭 극대화** (한 번에 많이). 가까운 거리 + 넓은 길.
- 대가 = 비싸고 용량 확장·교체 불가 → GPU·NPU·고성능 NIC 등 **대역폭이 생명인 곳**에만.
- von Neumann 병목(Unit 1)을 "통로를 극단적으로 넓혀" 푸는 방법.

### Q3. 용량 확장 및 교체/업그레이드에 대해 더 설명해줘

"왜 DIMM은 유연하고 HBM은 붙박이인가"를 물리적으로 풀어보자. 핵심은 **연결 방식의 차이** — 꽂는 것(socket) vs 붙이는 것(bonding)이다.

**DIMM — "꽂는" 방식이라 유연함**

```text
메인보드:
  [슬롯1][슬롯2][슬롯3][슬롯4]   ← 빈 슬롯에 막대기를 꽂았다 뺐다
     ▲
   DIMM 막대기 (탈착 가능)
```

**왜 확장·교체가 쉬운가:**

- **표준 소켓(슬롯)에 꽂는 구조** — 손으로 끼우고 뽑는다. 전기 접점이 슬롯 핀에 닿을 뿐, 영구 결합이 아님.
- **빈 슬롯에 더 꽂으면 용량 증가** — 8GB 쓰다가 슬롯에 16GB 하나 더 꽂으면 24GB. 메인보드가 허용하는 슬롯 수·최대 용량 안에서 자유.
- **고장나거나 더 큰 걸로 바꾸고 싶으면** 그 막대기만 뽑아 교체.
- **표준 규격(JEDEC)** 이라 어느 제조사 DIMM이든 호환.

→ 마치 **책장에 책을 더 꽂거나 빼는 것**처럼 유연.

**대가:** 꽂는 구조라 접점·거리가 길어져 — 신호가 멀리 가고 길이 좁아짐(대역폭 한계). 유연함을 얻고 대역폭을 일부 포기한 셈.

**HBM — "붙이는" 방식이라 붙박이**

```text
한 패키지 안:
  ┌──────────────────────────────┐
  │ [프로세서 다이]  [HBM 탑(적층)] │  ← 인터포저 위에 영구 본딩
  │ ──── 인터포저(받침 실리콘) ──── │
  └──────────────────────────────┘
       제조 공정에서 한 몸으로 굳힘
```

**왜 확장·교체가 불가능한가:**

- **제조 공정에서 프로세서와 함께 인터포저 위에 영구 결합(bonding)** 된다. 납땜·마이크로범프로 붙박이라 손으로 뽑을 수 없음.
- **슬롯이 없음** — 초광폭 버스(1024비트+)를 슬롯 접점으로 빼면 신호가 안 맞는다. 그래서 아주 짧고 촘촘한 배선으로 **고정** 연결해야 함. 이게 대역폭의 비결이자 붙박이의 원인.
- **용량이 칩 살 때 결정됨** — "이 GPU는 HBM 80GB" 식으로 **제조 시 확정**. 나중에 더 못 꽂음. 더 필요하면? **칩(가속기) 자체를 더 큰 모델로 통째 교체.**
- 한 층이라도 불량이면 그 HBM 탑(또는 패키지 전체)을 버려야 함 → 수율·비용 부담.

→ 마치 **벽에 붙박이로 짜 넣은 수납장** — 자리에 딱 맞고 효율적이지만, 더 넣거나 옮길 수 없음.

**핵심 트레이드오프 — 왜 이렇게 갈렸나**

```text
            연결 방식       대역폭     유연성(확장/교체)
DIMM        소켓(꽂음)       보통       높음 (슬롯 추가·교체 자유)
HBM         본딩(붙임)       매우 높음   없음 (제조 시 고정)
```

**근본 원리:** "초광폭·초단거리 연결"과 "탈착 가능"은 **물리적으로 양립이 어렵다.**

- 넓고 짧은 길(대역폭↑)을 만들려면 → 촘촘하게 영구 고정해야 함 → 못 뺌.
- 뺐다 꽂으려면(유연) → 표준 슬롯·긴 접점이 필요 → 길이 좁고 길어짐(대역폭↓).

HBM은 **대역폭을 위해 유연성을 버린** 선택이고, DIMM은 **유연성을 위해 대역폭을 양보한** 선택이다.

**실무적 함의**

- **HBM 시스템은 용량을 "미리·넉넉히" 사야 함** — 나중에 못 늘리니까. AI 가속기 고를 때 "HBM 몇 GB"가 중요한 스펙이 되는 이유.
- **DIMM 시스템은 "일단 적게 사고 나중에 추가"가 가능** — 서버 운영에서 비용 유연성.
- **고장 대응:** DIMM은 그 막대기만 교체 / HBM은 사실상 칩 전체 교체 (수리비·다운타임 차이).

**정리**

- **DIMM = 소켓에 꽂는 방식** → 슬롯 추가·교체·업그레이드 자유, 대신 대역폭은 보통.
- **HBM = 제조 시 인터포저에 영구 본딩** → 용량이 칩 살 때 고정, 못 뺌·못 늘림, 대신 초고대역폭.
- 이유: **"넓고 짧은 연결(대역폭)"과 "탈착 가능(유연성)"은 물리적으로 상충** → 둘 중 하나를 택한 결과.
