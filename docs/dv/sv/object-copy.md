# 객체 복사 — 핸들 복사 vs Shallow Copy vs Deep Copy

> `class`에서 `b = a;` 대입 시 벌어지는 **리모컨(핸들) 공유 함정**과, 진짜 복사본을 만드는 **Shallow Copy(`b = new a;`) vs Deep Copy(`b.copy(a)`)**의 차이 정리.

---

## 1. `b = a;` 대입 시 벌어지는 일 (리모컨 공유)

일반 변수(또는 `struct`)에서 `b = a;`는 **진짜 내용물을 통째로 복사**하지만, `class`에서 `b = a;`는 상자가 아니라 **"같은 상자를 가리키는 리모컨(핸들/주소)"만 복사**한다.

```text
[일반 값 복사 : b = a]                    [class 핸들 복사 : b = a]
  a ──> [상자 1 : addr = 10]                a ──┐
  b ──> [상자 2 : addr = 99] (별개 상자!)   b ──┴─> [똑같은 상자 1개 : addr = 99] (같이 바뀜! 🚨)
```

```systemverilog
pkt_c a, b;
a = new();    // 상자 1개 생성
a.addr = 10;
b = a;        // 상자가 복사되는 게 아니라, 같은 상자를 가리키는 리모컨만 복사됨!
b.addr = 99;  // b로 바꿨더니 a.addr도 같이 99로 바뀌어버림! 🚨
```

---

### `a = new; b = new; b = a;`처럼 둘 다 `new`를 한 뒤 대입하면?

앞에서 `b = new;`로 새 상자를 따로 만들었더라도, 다음 줄에 **`b = a;`를 쓰는 순간 똑같이 리모컨(핸들) 복사**가 된다.

1. **`a = new;`** → `[상자 1]`이 만들어지고 `a`가 가리킴
2. **`b = new;`** → `[상자 2]`가 만들어지고 `b`가 가리킴 (여기까지는 상자가 2개)
3. **`b = a;`** → `b`가 원래 가리키던 `[상자 2]`로 가는 줄을 끊어버리고, **`a`가 가리키는 `[상자 1]`로 화살표를 옮겨버림!**

```text
[b = new; 직후]                [b = a; 실행 후]
  a ──> [상자 1]                 a ──┐
                                 b ──┴─> [상자 1] (결국 또 상자 1을 같이 씀!)
  b ──> [상자 2]                         [상자 2] (아무도 안 가리켜 미아가 되어 버려짐 🗑️)
```

!!! warning "실무 함정: Monitor에서 매번 `tr = create()`로 새 상자를 만들어야 하는 이유"
    만약 Monitor에서 `create()`를 맨 처음에 한 번만 하고 루프를 돌 때마다 같은 `tr`에 값을 덮어쓰며 Scoreboard로 보내면, `class`는 리모컨만 전달되기 때문에 **Scoreboard가 옛날에 받아둔 상자들의 값까지 전부 최신 값으로 덮어써지는 대참사**가 난다.

---

## 2. 핸들 복사 vs Shallow Copy vs Deep Copy 완벽 비교

진짜로 상자를 따로 두면서 내용물을 베끼려면 **Shallow Copy** 또는 **Deep Copy**를 써야 한다. 두 방식의 차이는 **"큰 상자(`pkt`) 안에 또 다른 작은 상자(하위 클래스 객체 `sub_hdr`)가 들어있을 때, 그 안쪽 작은 상자까지 새로 만드느냐"**다.

```text
① 핸들 복사 (b = a;)          ② Shallow Copy (b = new a;)           ③ Deep Copy (b.copy(a);)
a ──┐                         a ──> [큰 상자 1] ──┐                  a ──> [큰 상자 1] ──> [작은 상자 1]
b ──┴─> [큰 상자 1]                               ├──> [작은 상자]   b ──> [큰 상자 2] ──> [작은 상자 2]
         └──> [작은 상자]     b ──> [큰 상자 2] ──┘   (안쪽은 공유!)       (겉도 속도 100% 별개! ✅)
```

| 방식 | 문법 | 겉 상자 (객체 자신) | 안쪽 작은 상자 (하위 객체) | 결과 |
| --- | --- | --- | --- | --- |
| **핸들 복사 (Handle Assignment)** | `b = a;` | **1개 공유** | **1개 공유** | `b`의 어디를 고쳐도 `a`가 같이 바뀜 |
| **얕은 복사 (Shallow Copy)** | `b = new a;` | **새로 생성 (2개)** | **1개 공유 ⚠️** | `b.addr = 99;`는 독립이지만, `b.sub_hdr.id = 7;`을 고치면 `a.sub_hdr.id`도 같이 바뀜 |
| **깊은 복사 (Deep Copy)** | `b.copy(a);` 또는 `$cast(b, a.clone());` | **새로 생성 (2개)** | **새로 생성 (2개) ✅** | 겉 상자부터 속 안의 작은 상자까지 100% 남남 (UVM 표준 방식 → [`uvm_object` 상세](../uvm/object.md)) |

```systemverilog
// 1) Shallow Copy (SystemVerilog 기본 문법): 겉 상자만 새로 만들고 안쪽 객체 핸들은 공유
b = new a;

// 2) Deep Copy (UVM 권장 방식): 속 안의 하위 객체까지 모두 별개로 복사
b = pkt_c::type_id::create("b");
b.copy(a);              // 또는 $cast(b, a.clone());
```

!!! note "하위 객체가 없으면 Shallow Copy와 Deep Copy는 같을까?"
    **100% 같다!** Shallow Copy든 Deep Copy든 **겉의 큰 상자(새로운 object)를 하나 새로 만드는 것은 동일**하다. 클래스 안에 또 다른 클래스 객체가 없고 일반 변수(`addr`, `data` 같은 숫자)만 들어있다면 두 방식의 결과는 완전히 똑같다.
