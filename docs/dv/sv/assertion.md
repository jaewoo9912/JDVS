# assertion (SVA — SystemVerilog Assertions)

> "이 조건은 **항상 참이어야 한다**"를 회로 옆 **자동 감시 카메라(CCTV)**처럼 코드로 박아두고, 깨지는 순간 시뮬레이터가 **시각·위치까지 짚어** 알려주는 기능.

## 핵심

- 검증은 보통 **scoreboard가 결과값**을 비교한다. assertion은 그 사이의 **프로토콜·타이밍 규칙**(handshake, FSM 상태 전이, 순서, 안정성 등)을 신호 레벨에서 직접 감시한다.
- 규칙이 깨지면 그 **클럭·신호·위치**를 즉시 출력 → 로그를 거슬러 추적할 필요가 없다.
- "버그가 **퍼지기 전에**, 발생 지점에서" 잡는 게 목적. (scoreboard는 멀리 떨어진 결과에서 잡힘)

```systemverilog
// FSM 감시 예: 지금 IDLE이고 start==1이면, 다음 클럭엔 무조건 BUSY여야 한다!
assert property (@(posedge clk)
  (state == IDLE && start) |=> (state == BUSY)
);
```

- 왼쪽(`state == IDLE && start`): **언제 감시를 시작할지(방아쇠)**
- 오른쪽(`state == BUSY`): **그때 반드시 일어나야 하는 결과**

## 비유: 계약서의 "반드시" 조항

| 계약서 | 검증(SVA) |
|---|---|
| "송장을 받으면 **3일 안에** 대금을 지급한다" | "`req`가 뜨면 **5클럭 안에** `ack`가 와야 한다" |
| 위반 시 즉시 분쟁 기록 | 위반 시 즉시 `$error`로 시각·신호 출력 |

## 두 종류 — immediate vs concurrent (`property`의 유무)

비유하면 **그 순간 찍는 사진 한 장(Immediate)**이냐, **매 클럭마다 계속 찍는 CCTV 동영상(Concurrent)**이냐의 차이다. 코드에서 눈에 보이는 가장 큰 구분 기준은 **`property` 키워드가 있느냐 없느냐**다.

| 구분 | Immediate (`assert (...)`) | Concurrent (`assert property (...)`) |
|---|---|---|
| **비유** | 그 줄을 지나는 순간 찍는 **사진 한 장** | 클럭마다 백그라운드로 계속 찍는 **CCTV 동영상** |
| **문법 구분** | **`property` 없음** (`if`문에서 `if`만 `assert`로 바꾼 모양) | **`property` 있음** (`@(posedge clk)`, `disable iff` 포함) |
| **시간 표현 (`##`, `\|->`, `\|=>`, `[*]`)** | **불가능** (현재 순간의 참/거짓 식만 가능, 시간 기호 쓰면 문법 에러) | **가능** (여러 클럭에 걸친 시간 순서·반복 표현) |
| **쓰는 위치** | `always_comb`, `initial`, `task/function` 블록 **안** | `module`, `interface` **안** (절차 블록 바깥) |
| **글리치 영향** | 그대로 받음 (신호가 바뀌는 과도기에 가짜 에러 가능 → `assert final`로 보완하기도 함) | 안 받음 (클럭 엣지의 안정된 값만 샘플링) |

```systemverilog
// 1) Immediate (property 없음) — 블록 안에서 "지금 당장 이 값이 맞나"만 체크
always_comb begin
  assert (!(a && b)) else $error("둘 다 1임!");
end

// 2) Concurrent (property 있음) — 한 줄로 바로 쓰거나, property에 이름을 붙여 두 줄로 나눠 씀
assert property (@(posedge clk) disable iff (!rst_n)
  req |-> ##[1:5] ack
) else $error("req 후 5클럭 내 ack 없음");

// (실무에서 자주 쓰는 두 줄 분리형 — 어차피 assert property가 있으면 무조건 Concurrent!)
property p_handshake;
  @(posedge clk) disable iff (!rst_n)
  valid |-> ##[1:3] ready;
endproperty
a_handshake: assert property (p_handshake);
```

> 실무에서 흔히 "SVA를 짠다 / 읽는다"고 할 때의 90% 이상은 **`property`가 붙은 Concurrent Assertion**이다.

### 왜 조합 논리 결과를 검사할 때도 `@(posedge clk)`를 쓸까?

조합 논리(`assign done_pulse = (state == DONE);`) 자체는 클럭과 무관하게 입력이 바뀌면 즉시 바뀐다. 그럼에도 concurrent assertion에 `@(posedge clk)`를 적는 이유는 **감시 카메라가 사진을 찍을 안전한 기준 시점**이 필요하기 때문이다.

- 클럭과 클럭 사이(과도기)에는 조합 회로에 **글리치**가 튀거나, 시뮬레이터 안에서 `state`가 먼저 `DONE`으로 바뀌고 아직 `assign`이 실행되기 직전(`done_pulse == 0`)인 찰나가 존재한다.
- 클럭 없이 매 순간 감시하면 신호가 바뀌는 중간 과정을 찍어 **억울한 가짜 에러(오경보)**가 터진다.
- 따라서 **"계산과 글리치가 다 가라앉아 조용해진 `posedge clk` 정각에만 사진을 찍되, 같은 사진 안에 두 조건이 함께 맞는지(`|->`) 확인하라"**는 뜻으로 `@(posedge clk)`를 쓴다.

## 화살표 두 개: `|->` (0칸 이동) vs `|=>` (1칸 이동)

| 화살표 | 이름 | 보드게임 칸 이동 | 결과 확인 시점 | 주로 쓰는 곳 |
|---|---|---|---|---|
| **`\|->`** | overlapped implication | **0칸 이동** (`\|-> ##0`과 동일) | 조건이 맞은 **바로 그 클럭** | 조합 논리 출력처럼 **즉시** 나와야 하는 결과 |
| **`\|=>`** | non-overlapped implication | **1칸 이동** (`\|-> ##1`과 동일) | 조건이 맞은 **다음 클럭** | 플립플롭(`always_ff`, `<=`)을 거쳐 **1클럭 뒤에** 나오는 결과 |

```systemverilog
// 1) |-> : DONE 상태인 바로 그 클럭에 done_pulse도 1이어야 함 (조합 출력)
assert property (@(posedge clk)
  (state == DONE) |-> (done_pulse == 1)
);

// 2) |=> : 지금 DONE 상태면 다음 클럭에는 IDLE로 돌아가야 함 (순차 전이, |-> ##1 과 동일)
assert property (@(posedge clk)
  (state == DONE) |=> (state == IDLE)
);
```

### `|->` / `|=>` 뒤에 `##숫자`가 붙을 때 칸 계산법 (덧셈 규칙!)

`**|->`는 0칸**, **`|=>`는 1칸**으로 생각하고 뒤에 붙은 `##숫자`를 그대로 더하면 몇 번째 클럭에서 확인하는지 바로 나온다.

```text
클럭 칸 :  [E1] ──1칸──> [E2] ──1칸──> [E3]
req     :   1
|-> ##1 :  (0칸) ──────> 여기서 ack 확인! (0 + 1 = 1칸 뒤인 E2)
|=> ##1 :        (|=>로 1칸) ──(##1로 1칸)──> 여기서 ack 확인! (1 + 1 = 2칸 뒤인 E3)
```

- `req |-> ##[1:10] ack` : `0 + (1~10)` = **1~10클럭 이내**에 `ack` 확인 (숫자 계산이 직관적이라 실무에서 뒤에 `##`을 쓸 땐 앞 화살표를 `|->`로 맞추는 경우가 많음)
- `req |=> ##[1:10] ack` : `1 + (1~10)` = **2~11클럭 이내**에 `ack` 확인

## SVA 시퀀스 기본 공식 (IEEE 1800 표준 문법)

SVA의 시퀀스 표현은 정규표현식(Regex)에서 기호를 따온 레고 블록 구조로, 아래 **한 가지 공식**이 반복된다.

> **`[신호A][몇 클럭 유지할지]   ##[몇 클럭 뒤로 갈지]   [신호B][몇 클럭 유지할지]`**

즉 **"신호(얼마나 연속 high로 유지)"** 블록들을 **"시간 이동(`##`)"**으로 이어 붙이는 구조다.

### 1. 신호 뒤에 붙는 `[*...]` — 몇 클럭 연속 유지할까? (반복)

- 생략 (`A`) : `A`가 **1클럭** 동안 참 (`A[*1]`과 같음)
- `A[*3]` : `A`가 쉬지 않고 **3클럭 연속** 참 (`A ##1 A ##1 A`를 줄여 쓴 것 — 끝나면 내 말은 3번째 칸에 서 있음)
- `A[*1:4]` : `A`가 **1~4클럭 연속** 참
- `A[*1:$]` : `A`가 **1클럭부터 무한대(`$`, 끝이 정해지지 않음)까지 연속** 참
- 0(low) 유지를 보고 싶으면 `(!A)[*3]`처럼 부정해서 쓴다.

### 2. 신호 앞에 붙는 `##...` — 다음 신호를 몇 칸 건너뛰어 볼까? (시간 이동)

- `##1` : 앞 구간이 끝난 뒤 **1칸 뒤(다음 클럭)**로 이동
- `##N` : 정확히 **N칸 뒤**로 이동
- `##[1:4]` : **1~4칸 뒤 사이 어딘가**에 한 번이라도 참이면 합격
- **`##0` : 0칸 이동 = 다음 클럭으로 넘어가지 않고, 앞 구간이 끝나는 바로 그 마지막 클럭에서 겹쳐서(동시에) 확인!**

### 3. 자주 헷갈리는 문법 Q&A 3가지

1. **왜 `busy[1:10]`이 아니라 `*`를 붙여서 `busy[*1:10]`으로 쓸까?**
   - `*` 없이 `busy[1:10]`이라고 쓰면 시뮬레이터가 클럭 반복이 아니라 **`busy` 신호의 1~10번 비트를 잘라낸 값(비트 슬라이싱, 예: `data[7:0]`)**으로 알아듣기 때문이다.
   - 따라서 신호 이름 뒤 대괄호에는 반드시 `*`를 붙여 **"이건 비트 번호가 아니라 클럭 반복 횟수야!"**라고 알려줘야 한다. 반면 `##[1:10]`은 앞에 이미 `##`(시간 이동 기호)이 있어 비트 번호와 헷갈릴 일이 없으므로 `*` 없이 쓴다.
2. **`start |=> [*3] busy`처럼 신호 앞에 `[*3]`을 쓸 수 있을까?**
   - **불가능(문법 에러)**. `[*3]`은 "무엇을 3번 반복할지" 대상을 알아야 하므로 반드시 **신호 이름 뒤**에 꼬리표처럼 붙여(`busy[*3]`) 써야 한다.
3. **`##[1:10] busy`와 `busy[*1:10]`은 같은 뜻일까?**
   - **놓이는 위치(신호 앞 vs 뒤)도 다르고 의미도 완전히 다르다!**
   - **`##[1:10] busy` (신호 앞 = 건너뛰어 한 번 체크)**: 1~10클럭 사이 어딘가에서 **딱 한 번만** `busy = 1`이면 통과 (나머지 클럭엔 0이어도 상관없음).
   - **`busy[*1:10]` (신호 뒤 = 안 끊기고 연속 유지)**: 중간에 한 번도 0으로 끊기지 않고 **1~10클럭 내내 연속으로** `busy = 1`이어야 통과.

```text
클럭                   :  E1   E2   E3   E4
##[1:10] busy          :   0    0    0    1   → 통과 ✅ (E1~E3은 0이어도 E4에 한 번 1이니까 OK)
busy[*1:10] ##1 done   :   1    1    1   done → 통과 ✅ (done 전까지 E1~E3 내내 1로 꽉 차 있어야 OK)
```

### 4. `##0` vs `##1` 완벽 비교 (택배 기사님 비유)

`$rose(valid) |-> valid[*1:$] ##0 ready` (또는 `valid until_with ready`)는 **"택배 기사님(`valid`)이 벨을 누르면, 문(`ready`)을 열어줄 때까지 문 앞을 떠나지 말고 계속 서 있어야 한다"**는 핸드셰이크 규칙이다. 여기서 `##0`과 `##1`의 차이는 결정적이다.

```text
클럭                   :  E1   E2   E3   E4
ready (문 열림)        :   0    0    0    1   (E4에서 드디어 문을 열어줌!)

[##0 일 때: valid[*1:$] ##0 ready]  (0칸 이동 = 마지막 칸 E4에서 겹침!)
valid                  :   1 ───1 ───1 ───1   ← 문이 열리는 E4 그 순간까지 valid=1 유지! (정상 핸드셰이크 ✅)

[##1 일 때: valid[*1:$] ##1 ready]  (1칸 이동 = valid 끝난 다음 칸에서 ready 체크)
valid                  :   1 ───1 ───1    0   ← E3까지만 서 있다가 문 열리기 직전(E4)에 가버려도(valid=0) 통과됨 ❌
                                     ↘ ##1 (한 칸 뒤인 E4에서 빈 문만 열려도 합격 처리)
```

- **`##0`**: `valid`가 1로 유지되고 있는 **바로 그 마지막 클럭(E4)에 `ready`도 동시에 1로 겹쳐서** 만나야 한다.
- **`##1`**: `valid` 행진이 끝난 **다음 클럭**에 `ready`가 1이면 되므로, 정작 `ready=1`인 클럭에 `valid=0`으로 떨어져도 통과해 버린다.

## 지난 클럭과 비교하는 함수 3총사 (`$rose`, `$fell`, `$stable`)

현재 클럭의 값만 보는 것을 넘어, **"직전 클럭과 비교해 어떻게 바뀌었는지"**를 검사하는 실무 필수 함수 3개다.

- **`$rose(신호)`**: 지난 클럭엔 `0`이었다가 이번 클럭에 `1`로 **막 올라간 첫 클럭에만** 참 (그냥 `req`라고 쓰면 1인 내내 매 클럭 감시가 새로 시작되지만, `$rose(req)`는 처음 올라간 순간 딱 한 번만 감시 시작).
- **`$fell(신호)`**: 지난 클럭엔 `1`이었다가 이번 클럭에 `0`으로 **막 내려간 순간에만** 참.
- **`$stable(신호)`**: 지난 클럭 값과 이번 클럭 값이 **바뀌지 않고 그대로 유지**되었으면 참 (1비트 신호뿐 아니라 32비트 데이터 버스 전체도 한 번에 검사).

```text
클럭         E1   E2   E3   E4
sig           0    1    1    0
$rose(sig)    X   참!  거짓 거짓   (0→1 올라간 E2만 참)
$stable(sig)  X  거짓   참! 거짓   (1→1 유지된 E3만 참)
$fell(sig)    X  거짓  거짓  참!   (1→0 내려간 E4만 참)
```

## 실무 Assertion 코드 읽기 단어장 & 5대 패턴 해석

실무 SVA 코드를 읽을 때는 아래 **단어장 7개**만 대입해 왼쪽에서 오른쪽으로 번역하면 90% 이상 바로 읽힌다. (실제 코드에서는 바깥에 `assert property (@(posedge clk) disable iff (!rst_n) ... );`가 감싸고 있다.)

| 기호 | 한국어 번역 |
|---|---|
| **`\|->`** | (왼쪽이 참이면) **바로 그 클럭에** (0칸 이동) |
| **`\|=>`** | (왼쪽이 참이면) **다음 클럭에** (1칸 이동) |
| **`##N` / `##[a:b]`** | **N클럭 뒤에** / **a~b클럭 사이 안에 한 번** (`##0`은 **끝나는 바로 그 클럭에 동시에**) |
| **`신호[*N]` / `[*a:b]`** | 신호가 안 끊기고 **N클럭(a~b클럭) 연속 1 유지** (`$`는 끝까지 쭉) |
| **`$rose(신호)`** | 신호가 **0 → 1로 막 올라갔을 때** |
| **`$fell(신호)`** | 신호가 **1 → 0으로 막 내려갔을 때** |
| **`$stable(신호)`** | 신호 값이 **지난 클럭과 똑같이 유지** |

### 실무 5대 대표 패턴 한 줄씩 해석하기

```systemverilog
// 패턴 1: 기본 응답 시간 체크 (##[a:b] — 건너뛰어 한 번 체크)
$rose(req) |-> ##[1:4] ack
// 해석: req가 0→1로 올라오면, 그 클럭 기준으로 1~4클럭 이내에 ack가 한 번 1이어야 한다. (중간 클럭엔 0이어도 됨)

// 패턴 2: 고정된 클럭 동안 신호 연속 유지 체크 ([*N] — 연속 도장 찍기)
$rose(err) |-> irq[*4]
// 해석: err가 막 발생하면, 바로 그 클럭부터 4클럭 동안 쉬지 않고 연속으로 irq=1을 유지해야 한다.

// 패턴 3: 대기 중 값 변경 금지 체크 (|=> + $stable)
(valid && !ready) |=> valid && $stable(data)
// 해석: valid는 1인데 상대가 아직 못 받으면(!ready), 다음 클럭에도 valid를 내리지 말고 data 값도 바꾸지 말아야 한다.

// 패턴 4: 연속 유지 후 완료 신호 체크 ([*a:b] + ##1)
start |=> busy[*1:8] ##1 done
// 해석: start가 1이면 다음 클럭부터 1~8클럭 동안 busy가 끊기지 않고 1로 유지된 직후, 그 다음 클럭(##1)에 done이 1이어야 한다.

// 패턴 5: 끝까지 유지되다가 같은 클럭에 만나기 ([*1:$] + ##0)
$rose(valid) |-> valid[*1:$] ##0 ready
// 해석: valid가 막 올라오면 중간에 0으로 떨어지지 않고 쭉 유지되다가([*1:$]), 마지막 클럭에 ready=1과 동시에(##0) 만나야 한다.
```

## 빌딩 블록: property / sequence / implication

```text
sequence  : 시간에 걸친 신호 패턴       (예: a ##1 b ##2 c)
property  : sequence + 함의/부정 등 규칙 (예: a |-> b)
assert    : property가 참인지 검사
```

```systemverilog
// req가 올라간 다음 클럭부터, 1~5클럭 내 ack
property p_req_ack;
  @(posedge clk) disable iff (!rst_n)
  req |=> ##[0:4] ack;
endproperty
assert property (p_req_ack) else $error("req→ack timeout");
```

## 자주 쓰는 연산자 요약

| 연산자 | 의미 | 예 |
|---|---|---|
| `\|->` / `\|=>` | 함의 (같은 클럭 `0칸` / 다음 클럭 `1칸`) | `valid \|-> ready` |
| `##0` | 앞 구간이 끝나는 **바로 그 클럭에 겹쳐서** | `valid[*1:$] ##0 ready` |
| `##N` / `##[m:n]` | 지연 / 지연 범위 (신호 **앞**에 표기, `*` 없음) | `a ##2 b`, `a ##[1:4] b` |
| `[*N]` / `[*m:n]` / `[*1:$]` | 연속 반복 (신호 **뒤**에 표기, 비트 슬라이싱 구분용 `*` 필수) | `busy[*3]`, `valid[*1:$]` |
| `until` / `until_with` | 조건까지 계속 유지 (미포함 / 해당 클럭 포함) | `valid until_with ready` |
| `[->N]` | go-to 반복 (N번째 발생까지) | `ack[->1]` |
| `$rose` / `$fell` | 상승/하강 엣지 | `$rose(req)` |
| `$stable` / `$past` | 값 유지 / 과거값 | `$stable(addr)`, `$past(data)` |
| `throughout` | 구간 내내 유지 | `(en) throughout (a ##1 b)` |
| `within` | 포함 | `s1 within s2` |

## disable iff — 리셋 중엔 검사 끄기

```systemverilog
assert property (@(posedge clk) disable iff (!rst_n)
  req |-> ##[1:4] ack);
```

> 리셋(`rst_n == 0`)이 걸리면 회로가 작업을 멈추고 초기화하므로 `ack`가 안 나오는 게 정상이다. `disable iff (!rst_n)`는 **리셋·예외 구간**에서 감시 카메라를 꺼서 가짜 에러(헛발)가 나지 않게 한다. 실무 SVA에서 거의 필수 세트.

## assert / assume / cover

| 지시어 | 의미 | 쓰임 |
|---|---|---|
| `assert` | 이 규칙은 **반드시 참** | 위반 시 fail (검증의 핵심) |
| `assume` | 이 규칙을 **참이라 가정** (입력 제약) | formal에서 입력 조건 한정 |
| `cover` | 이 시나리오가 **실제로 일어났나** | 자극이 의도한 경로를 쳤는지 커버리지 |

```systemverilog
// 이 코너케이스가 한 번이라도 발생했는지 측정
cover property (@(posedge clk) $rose(req) ##[1:3] $rose(ack));
```

## 흔한 패턴 모음

```systemverilog
// 1) one-hot: 항상 정확히 한 비트만 1
assert property (@(posedge clk) $onehot(state_oh));

// 2) valid 중 데이터 안정: valid이고 ready 아니면 data 유지
assert property (@(posedge clk) (valid && !ready) |=> $stable(data));

// 3) 요청-응답 짝: req 후 반드시 ack (timeout 포함)
assert property (@(posedge clk) $rose(req) |-> ##[1:8] ack);

// 4) 동시에 둘 다 1이면 안 됨 (mutual exclusion)
assert property (@(posedge clk) !(wr_en && rd_en));

// 5) FIFO: full이면 push 금지
assert property (@(posedge clk) full |-> !push);
```

## 어디에 두나

- **interface**에 넣으면 그 프로토콜을 쓰는 모든 곳에서 재사용된다 (가장 흔한 위치).
- 바인드(`bind`)로 RTL을 안 건드리고 DUT 내부 신호에 assertion을 붙일 수 있다.

```systemverilog
// RTL 수정 없이 외부에서 검사 모듈을 붙임
bind dut_top axi_protocol_checker u_chk (.clk(clk), .rst_n(rst_n), ...);
```

## 흔한 함정

- ❌ **클럭 빠뜨림** — `assert property (req |-> ack)`는 클럭이 없어 모호. 항상 `@(posedge clk)` 명시.
- ❌ **리셋 미처리** — `disable iff (!rst_n)` 없으면 리셋 중 헛발한다.
- ❌ `|->` vs `|=>` 혼동 — 같은 클럭 검사인지 다음 클럭인지에 따라 의미가 달라진다.
- ❌ **vacuous pass 오해** — 선행조건이 한 번도 안 맞으면 assertion은 "통과"로 뜬다. 진짜 검증됐는지는 `cover`로 따로 확인.

## 이 프로젝트 현황

RDMA TB는 scoreboard 기반 결과 비교가 중심이고, 프로토콜 레벨 SVA는 제한적이다. AXI/handshake 신호에 `interface` SVA나 `bind` checker를 더하면 버그를 **발생 지점**에서 더 빨리 잡을 수 있다.
