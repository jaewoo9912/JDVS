# X vs Z — `==` vs `===`, TB에서 X 잡기

> **`X`(값은 있는데 0/1을 모름)**와 **`Z`(아무도 구동 안 함)**의 차이, **`==` vs `===`**가 X/Z를 다루는 방식, 그리고 TB 체크에서 `X`를 놓치지 않는 법(`!==` / `$isunknown`).

---
## 1. `X` vs `Z`

| 값 | 의미 | 비유 | 생기는 곳 |
| --- | --- | --- | --- |
| **`X`** | 값은 **있는데** `0`인지 `1`인지 **모름** | 물음표 `?` | 리셋 안 된 FF / 메모리 초기값, 드라이버 충돌(`1` vs `0`), `X` 연산 결과, `Z`가 연산에 들어간 결과 |
| **`Z`** | **아무 값도 안 주는** 상태 | 선이 끊김 (손 뗌) | 드라이버 없는 `wire`, tri-state `en = 0`, `inout` 미구동 구간 |

- `Z`는 선 위에서는 `Z`로 보이지만, **연산(`&`, `+`, 비교 등)에 들어가는 순간 `X`처럼 취급**된다 (`1'bz & 1'b1 = x`).
- `Z`가 어디서 생기는지(tri-state, `inout`, 다중 드라이버 해석)는 → [wire / reg / logic §5](../syntax/net-variable.md#5-tri-state-inout-wire)

---

## 2. `==` vs `===` (논리 등호 vs case 등호)

| 연산자 | `X` / `Z`를 어떻게 보나 | 결과 값 | 합성 |
| --- | --- | --- | --- |
| **`==`** / `!=` | "모르는 값" → 판단 못 하면 **`X`** | `0` / `1` / **`X`** | 가능 (RTL용) |
| **`===`** / `!==` | `X`, `Z`도 **하나의 비트 모양**으로 보고 그대로 비교 | **항상 `0` / `1`** | **불가** → TB / SVA 전용 |

### `==`가 `X`를 내는 조건

- **확실한 비트(`0`/`1`) 중에 이미 다른 게 있으면 → `0`** (모르는 비트와 상관없이 다르다고 확정).
- **보이는 비트가 다 같은데 `X`/`Z` 때문에 판단을 못 할 때만 → `X`**.

```systemverilog
4'b10x0 == 4'b0010   // 0 : 최상위 비트가 1 vs 0 으로 이미 다름 → 확정
4'b10x0 == 4'b1010   // x : 나머지는 다 같은데 x 자리 때문에 판단 불가
4'b10x0 === 4'b10x0  // 1 : x 자리까지 모양이 똑같음
```

| A | B | `A == B` | `A === B` |
| --- | --- | --- | --- |
| `4'b1010` | `4'b1010` | `1` | `1` |
| `4'b1010` | `4'b1011` | `0` | `0` |
| `4'b10x0` | `4'b1010` | **`x`** | `0` |
| `4'b10x0` | `4'b10x0` | **`x`** | **`1`** |
| `4'b10z0` | `4'b10z0` | **`x`** | **`1`** |

!!! tip "실무 추천 — `$isunknown()`"
    `$isunknown(data)`는 **한 비트라도 `X` 또는 `Z`면 `1`**을 돌려준다. `data === 'x`처럼 쓰는 것보다 의도가 분명하고 모든 비트를 한 번에 검사한다.

    ```systemverilog
    if ($isunknown(data)) `uvm_error("XCHK", $sformatf("data has X/Z: %b", data))
    ```

## 3. TB 체크에서 `X`를 놓치는 함정 { #tb-x }

`if (조건)`은 조건이 `X`이면 **거짓**으로 보고 `else`로 간다. 그래서 `!=`로 비교하는 체크는 **`act`가 `X`일 때 에러를 못 띄운다.**

```systemverilog
// ❌ act = 8'bxxxx_xxxx 이면 (act != exp) = X → if 거짓 → 에러 안 뜸 (놓침!)
if (act != exp) `uvm_error("SCB", "mismatch")

// ✅ 방법 1: !== 는 항상 0/1 → X 도 "다르다"로 잡힘
if (act !== exp) `uvm_error("SCB", "mismatch")

// ✅ 방법 2: 먼저 X/Z 여부를 따로 체크
if ($isunknown(act))  `uvm_error("SCB", "act has X/Z")
else if (act != exp)  `uvm_error("SCB", "mismatch")
```

!!! warning "자주 틀리는 포인트 — scoreboard / checker는 `!==` 또는 `$isunknown`"
    - `==` / `!=`의 결과가 `X`이면 `if`는 **조용히 거짓 처리**한다 → `X`가 나온 버그가 **가짜 PASS**.
    - scoreboard / checker의 비교는 **`!==`**를 쓰거나, 비교 전에 **`$isunknown(act)`**로 먼저 걸러낸다.
    - `===` / `!==`는 **합성 불가**이므로 RTL에는 쓰지 않는다 (TB / SVA 전용).

---

## 4. 핵심 규칙 요약

- `X` = 값은 있는데 모름, `Z` = 아무도 구동 안 함. `Z`가 연산에 들어가면 `X`.
- `==`는 판단 못 하면 `X`, `===`는 `X`/`Z`까지 모양 비교해서 항상 `0`/`1`.
- `if (X)`는 거짓 → RTL에선 X-optimism(`xprop`으로 차단), TB에선 체크 누락.
- TB 체크는 **`!==` 또는 `$isunknown()`**. `===` / `!==`는 TB / SVA 전용.
