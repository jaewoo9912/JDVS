# Unit 1 — 왜 MMU가 필요한가? (Why MMU?)

## 한 줄 정의

> **MMU(Memory Management Unit)** 는 프로그램이 쓰는 **가상 주소(Virtual Address)** 를 실제 메모리 칩의 **물리 주소(Physical Address)** 로 **실시간 번역**해주는 하드웨어 관문이다.

## 배경 — 가상 메모리 이전의 3대 고통

여러 프로그램을 동시에 돌리면서 생긴 문제들:

1. **충돌 (Relocation)** — 여러 프로그램이 같은 물리주소를 원해서 서로 덮어씀
2. **보호 (Protection)** — A가 B의 메모리를 멋대로 읽고 망가뜨림 (보안 구멍)
3. **용량 (Capacity)** — 물리 RAM보다 큰 메모리를 쓰고 싶음

→ 이 셋을 한 번에 해결한 아이디어가 **가상 메모리**, 그걸 하드웨어로 실현하는 부품이 **MMU**.

## 핵심 비유 — 호텔 프런트 데스크

- 손님(프로그램)은 모두 "내 101호"(가상주소)라고 편하게 부름
- 프런트 데스크(MMU)가 그때그때 **진짜 방 번호**(물리주소)로 안내
- 손님 A의 101호 = 3층 7번방, 손님 B의 101호 = 5층 2번방 → **충돌 없음, 서로 못 봄**

```text
   프로그램 A          프로그램 B
   "0x1000 줘"        "0x1000 줘"
       │                  │
       ▼                  ▼
   ┌─────────────────────────┐
   │          MMU            │   ← 프런트 데스크
   └─────┬──────────────┬────┘
         ▼              ▼
   물리 0x8000      물리 0x3000      ← 진짜로는 다른 곳!
```

## 작동 원리 (큰 그림)

1. CPU(또는 RDMA 엔진)가 **가상 주소**로 메모리 접근 요청
2. 메모리에 닿기 **전에** MMU가 가로채서 물리 주소로 번역
3. 번역된 물리 주소로 진짜 메모리에 접근
4. 매핑이 없거나 권한이 없으면 → **fault(에러)** 발생

> 핵심: MMU는 모든 메모리 접근이 **반드시 거쳐가는 관문**이다.

## 흔한 오해

- **"MMU는 소프트웨어다?"** → ❌ 매핑 규칙을 **정하는 건 OS(SW)**, 매 접근마다 **번역을 집행하는 건 MMU(HW)**. ("규칙은 SW가 만들고, 집행은 HW가 한다.")
- **"가상주소는 암호화?"** → ❌ 숨기는 게 아니라 **다른 번호로 re-mapping**할 뿐.

## 핵심 takeaway

- MMU = 가상→물리 번역기. 충돌/보호/용량 문제를 해결한다.
- 모든 접근이 관문을 지나므로 **번역은 반드시 빨라야 한다** → 이를 위한 장치가 TLB (Unit 4).
- "같은 가상주소 → 다른 물리주소" 덕분에 컴파일러는 모든 프로그램을 **항상 0x0부터 시작**한다고 가정하고 컴파일할 수 있다.

## 📎 부록 — 이 단원에서 나온 질문들

### Q1. 물리 RAM이 4GB인데 8GB를 쓰고 싶으면 MMU가 어떻게 해결하나? 결국 4GB가 물리적 한계 아닌가?

- **맞다. 4GB는 진짜 물리 한계다.** MMU가 RAM을 늘려주는 게 아니다.
- 트릭: **8GB를 동시에 다 쓰지는 않는다.** 지금 쓰는 부분만 RAM(4GB)에 올리고, 안 쓰는 부분은 **디스크(swap/page file)** 에 치워둔다. RAM+디스크를 합쳐 8GB인 "착시"를 만든다.
- **비유(책상과 책장):** 책상(RAM)엔 4권만 올라감. 5번째 책이 필요하면 안 쓰는 책을 책장(디스크)에 꽂고 필요한 책을 꺼내옴. 계속 바꿔치기(swap)하면 8권으로 공부 가능. 느릴 뿐.
- **MMU의 역할:** 변환표의 **present bit**(이 페이지가 지금 RAM에 있나?)을 보고, 없으면 **PAGE FAULT** 알람을 울림 → OS가 디스크에서 RAM으로 가져옴 → 표 갱신 → 재시도.
- **대가:** 디스크는 RAM보다 수만 배 느림. swap이 잦으면 버벅임("thrashing").
- ※ 우리 프로젝트의 RDMA용 MMU는 보통 디스크 swap까지는 안 하고 **주소 변환과 보호**에 집중한다 (Unit 6에서 재론).

### Q2. RAM이 CPU와 가장 가까운(가장 빠른) 메모리인가?

- **아니다.** RAM보다 더 가깝고 빠른 것들이 있다. 이것이 **메모리 계층(memory hierarchy)**.
- 가까운 순서: **레지스터 → L1 → L2 → L3 캐시 → RAM(DRAM) → SSD/디스크**
- RAM은 "메인 메모리"로, CPU 칩 **밖** 메인보드에 있다. 캐시보다 멀지만 디스크보다는 압도적으로 빠름 (대략 RAM ~200 사이클, 디스크 수만~수십만 사이클).
- **왜 계층이 있나:** "빠른 건 비싸서 조금밖에 못 만들고, 큰 건 느리다"는 물리적 타협.
- **반복되는 패턴:** "더 빠르고 작은 곳에 지금 쓰는 것만 두고, 없으면 더 느리고 큰 곳에서 가져온다." (레지스터↔캐시, 캐시↔RAM, RAM↔디스크에서 모두 반복). **TLB도 이 패턴의 한 사례** = "주소 변환표 전용 캐시".
